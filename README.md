# Sole Spectrum

Sole Spectrum is an academic shoe-commerce demo showing how commerce behavior can travel from a React storefront into an Adobe Client Data Layer-style queue, an XDM ExperienceEvent payload, the Adobe Web SDK adapter, and conceptual Audience Manager classification.

## Objective

A completed purchase classifies every line item by the **final unit price actually paid**, before delivery charges. Product merchandising tier is retained separately, so a premium-tier shoe discounted to INR 5,599 remains `productTier: premium` but has `purchasePriceBand: mid_range`.

This repository uses synthetic customer identity only. It is not a payment system and contains no Adobe credentials.

## Stack and Install

- React, Vite, JavaScript, React Router
- Local JavaScript catalog and localStorage cart/customer state
- Vitest for domain and analytics tests
- Adobe Client Data Layer-style `window.adobeDataLayer`
- Safe `alloy('sendEvent', { xdm })` adapter when configured

```bash
npm.cmd install
copy .env.example .env
npm.cmd run dev
npm.cmd test
npm.cmd run build
```

PowerShell may block `npm.ps1` on some Windows machines; `npm.cmd` avoids changing execution policy.

## Environment

`.env.example` contains placeholders only:

- `VITE_ADOBE_ENABLED=false`
- `VITE_ADOBE_DEBUG=true`
- `VITE_ADOBE_DATASTREAM_ID=`
- `VITE_ADOBE_ORG_ID=`
- `VITE_ADOBE_TENANT_NAMESPACE=`
- `VITE_ADOBE_CUSTOMER_NAMESPACE=ShoeStoreCustomerID`

Demo mode works without these values. When disabled or when `window.alloy` is unavailable, payloads are logged and the storefront continues.

## Price Rules

`classifyPriceBand(finalUnitPrice)` returns:

| Final unit price | Value |
|---|---|
| `< INR 2,000` | `budget` |
| `INR 2,000` through `INR 5,999` | `mid_range` |
| `>= INR 6,000` | `premium` |

The order-level `highestPriceBand` hierarchy is `premium > mid_range > budget`; item-level values remain available in `productListItems`.

## Journey and Event Matrix

| Journey action | Internal event | XDM signal | Purchaser signal? |
|---|---|---|---|
| Route loaded | `pageView` | `web.webpagedetails.pageViews` | No |
| Product card/detail | `productClick`, `productDetailView` | `commerce.productViews` | No |
| Search/filter | `search`, `filterInteraction` | web interaction | No |
| Add/remove cart | `addToCart`, `removeFromCart` | product list adds/removals | No |
| Checkout | `checkoutInitiation` | `commerce.checkouts` | No |
| Confirmation | `purchase` | `commerce.purchases` | **Yes** |
| Identity toggle | synthetic login/logout | identity-bearing event when applicable | No |

Each action builds one normalized object, pushes it to `window.adobeDataLayer`, builds one XDM payload, and calls the adapter once. The development inspector shows the latest values.

## Testing and Validation

`npm.cmd test` covers price boundaries, discounted totals, mixed-order classification, item-level XDM bands, missing Alloy fallback, and duplicate purchase protection. Use browser developer tools to inspect `window.adobeDataLayer` and `window.__soleSpectrumLastAnalytics`. Then validate network delivery with Adobe Experience Platform Debugger and Assurance after Tags is configured. Confirm signal names in Audience Manager's Unused Signals report before production trait rules.

## Privacy and Limitations

No real names, emails, payment information, ECIDs, or credentials are generated by the application. The checkout name/city are mock demo values held only in session storage for the confirmation screen. Anonymous identity is left to the Web SDK/Experience Cloud identity handling. The custom XDM paths are illustrative and must match the custom field group in the Adobe sandbox.

Future work could add inventory, server-side order persistence, consent management, currency localization, and automated browser tests.
